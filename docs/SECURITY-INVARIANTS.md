# Security invariants

These IDs describe the current source, not the protection available in older installed releases. Racks 1.4.0 and earlier do not verify update manifest signatures. See [STATUS.md](../STATUS.md) for release readiness and [ARCHITECTURE.md](ARCHITECTURE.md) for the boundaries and guard limitations.

- **INV-FS-1:** User-data mutations go through `FileOperationBroker`, with path validation, protected-folder checks, on-disk confirmation and one audit record per call; reparse points are handled without recursive traversal of their targets. Recycling refuses network/non-fixed drives, but Windows can still permanently delete on a fixed drive with a disabled or undersized bin (`FileOperationBroker`, `SafeMove`, `SafeDelete`).
- **INV-FS-2:** Typed names and destination leaf names cannot express paths, traversal, streams, reserved devices or trailing dots/spaces; full paths are validated before mutation (`PathPolicy`, `FileOperationBroker`).
- **INV-IDS-1:** Persisted/imported `AssignedFiles` entries must be plain leaf names; invalid entries are dropped and workspace return validates the name again before combining paths (`RackSettingsValidator`, `WorkspaceReturn`).
- **INV-REG-1:** Presentation accesses app-wide registry switches and migration markers through `AppSettings` / `MigrationMarkers`, enforced by `RegistryAccessGuardTests` within its documented scanning limits.
- **INV-REG-2:** Per-rack settings and global style defaults use `RackSettingsRepository` and one `RackSettingsSchema`; values are validated before application, rejected/adjusted values are audited and valid settings of other racks remain loadable (`RackSettingsValidator`).
- **INV-IMPORT-1:** Layout validation completes before registry writes; imported paths must be local drive paths, empty or known sentinels, and unsafe names, network/device paths or unsafe resources reject the whole file; user-picked network folders remain supported (`LayoutSecurityPolicy`, `LayoutValidator`).
- **INV-IMPORT-2:** Import snapshots affected registry values, writes and verifies them, then attempts and checks rollback on failure; failed rollback is reported/audited and attempts a recovery-file save whose failure is also reported; nested subkeys are not snapshotted and recovery files only represent supported layout values (`LayoutImportExecutor`).
- **INV-IMPORT-3:** Fonts, colors and background images are validated before WPF resource parsing: plain font names, safe color forms and local image paths only, preventing embedded resource locations from contacting remote hosts (`SafeWpfValues`, `Instance`, `LayoutSecurityPolicy`).
- **INV-IMPORT-4:** SVG thumbnails disable external images, elements, XML entities and DTD processing at startup and before each parse (`SafeSvg`, `AppBootstrapService`).
- **INV-IMPORT-5:** Layout parsing bounds file size, JSON depth, rack and field counts and rejects malformed shape, duplicates and unsupported versions; validation caps regexes/lists, checks rack identity and drops or normalizes recoverable bad scalar/list values with a report instead of rejecting legacy backups (`LayoutLimits`, `LayoutParser`, `LayoutValidator`).
- **INV-ROUTE-1:** Auto-route uses bounded regex evaluation without deleting saved bad rules, skips unsafe names, unfinished/hidden/system items, links and online-only cloud files, retries in-use files within a bound, and moves through the broker with audited decisions (`RoutingPolicy`, `AutoRouteService`, `SafeRegex`, `Instance`, `AutoRouteRuleDialog`).
- **INV-REMOVE-1:** Removing a sandboxed rack returns its contents before attempting empty-folder deletion; failed returns keep the data, and a Desktop rack folder that remains after removal is reported (`UninstallCleanup.ReturnFolderToDesktop`, `RackFolderRemoval`, `RackWindow.Menu`).
- **INV-UNINSTALL-1:** Uninstall returns unique data by same-volume rename without overwriting Desktop names, unlinks pointers/extra hardlink names, deletes only empty or Racks-owned content, and keeps/report leftovers when return fails; repeated cleanup is safe (`UninstallCleanup`).
- **INV-UPDATE-1:** Updates require a manifest signed by the embedded key, the exact release tag and a newer version, an allowed HTTPS release URL, and installer size/SHA-256 matching the manifest; missing/mismatched trust fails closed and messages name only verified versions (`UpdateService`, `ReleaseManifestValidator`, `UpdateMessages`, `UpdateManifest`).
- **INV-EXEC-1:** The installer downloads into a fresh owner-only directory with exclusive creation, bounded size and timed reads; size/hash verification uses a read-only handle denying writes/deletes held until process start, and launch failure keeps Racks running (`InstallerExecutor`).
- **INV-RELEASE-1:** Release signing builds nothing, uses the pinned signer, verifies the signed tag and draft/build artifacts and requires explicit confirmation before signing/publishing; optional SignPath signing is off by default and verifies Authenticode when enabled (`tools/release-sign.ps1`, `.github/workflows/release.yml`, `ReleaseScriptTests`, `ReleaseWorkflowSigningTests`).
